# v0.1.9 — Authorization scope recovery

## 中文

本版本修复任务重新打开后的授权范围错误。旧逻辑会把没有持久化路径的预览显示为“桌面、下载”，再次执行时把这两个中文标签当作文件路径提交，后端因此得到空的授权目录并报“执行任务超出了授权的目录”。现在任务保存预览目录，重新打开时只提交绝对路径；旧任务中的无效显示标签会自动回退到根据任务描述推导的目录。

执行器同时接受授权目录中的绝对子目录、规范化路径和符号链接对应路径，并识别 `desktop`、`downloads`、`workspace`、`selected` 以及中文目录别名。授权检查仍然禁止访问授权目录之外的路径，也不会把只授权的子目录扩大成整个桌面。

验证：`npm test -- --run` 通过（27 tests）；`npm run check` 通过；Electron 闭环测试用两个普通名称的 `.dmg` 文件通过，渲染错误为 0。

## English

This release fixes authorization failures after reopening a task. The previous UI displayed missing persisted paths as the labels “桌面” and “下载”, then submitted those labels as filesystem paths. The server discarded them, leaving no approved roots and reporting that execution exceeded the authorized directory. Preview roots are now persisted and reopened tasks submit absolute paths; legacy invalid labels fall back to roots inferred from the task.

The executor also accepts authorized absolute subdirectories, normalized paths, symlink-equivalent paths and localized scope aliases. It still rejects paths outside the approved roots and never broadens a selected subdirectory grant to the whole Desktop.

Validation: `npm test -- --run` passed (27 tests); `npm run check` passed; the Electron closed loop moved two ordinarily named `.dmg` files with zero renderer errors.
